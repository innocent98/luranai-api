CORS Guide (Tenant Version, Custom Integrations Only)

For most tenants using the standard widget snippet, you do not need this.

When CORS matters
- You are building a custom frontend that calls Luran APIs directly.
- Your frontend domain is different from your API domain.

Typical symptoms
- Browser shows CORS errors in console.
- API works in tools like Postman, but fails in browser.

What must be configured
- Your frontend origin must be allowed by platform backend CORS policy.
- Origin must match exactly (protocol + domain + port if present).

Examples
- `https://app.example.com`
- `https://www.example.com`
- `http://localhost:3000` (development)

Important notes
- If you use multiple domains/subdomains, each must be added.
- After CORS config changes, backend service must be restarted.

If you are using the official widget and still seeing issues
- Confirm widget script loads from CDN.
- Confirm `tenantId` and public API key are correct.
- Confirm API key belongs to that tenant.
- Contact support with browser console and network error details.
